## C. Routing Architecture

`lib/src/routing/app_router.dart` memiliki registry, root key, navigator shell, safe error UI dan lifecycle router. `route_policy.dart` memutuskan redirect secara sinkron tanpa HTTP/JWT decoding. `route_refresh_notifier.dart` memfilter `(SessionPhase, user.id, user.peran)` dan menurunkan epoch lifecycle. `account_overlay_observer.dart` mencatat hanya pageless overlay pada lokasi akun, agar modal lama dibuang pada perubahan scope walaupun URL tetap sama. Ia tidak menghapus Page deklaratif.

GoRouter tunggal memakai API `GoRouter.routingConfig`. Config dan navigator branch privat diganti hanya ketika identitas/epoch scope berubah; ini diperlukan agar retained branch/profil akun A tidak dipakai akun B. Konfigurasi tidak dibuat ulang pada setiap tab/build/token refresh. Boundary menangkap scope yang membangunnya: boundary lama menjadi kosong segera, sehingga tidak membuat owner sementara untuk identitas baru sebelum config baru diterapkan. Display memiliki path/key tetap sehingga pergantian config akun tidak mengganti host device.

## E. Session & Security

QueueApi dan SessionStore existing tetap satu-satunya pemilik sesi. Router tidak menyimpan token/user projection baru, decode JWT, melakukan auth GET tambahan, atau menjalankan POST. Lima SessionPhase dipertahankan; offline/storageError menampilkan recovery, tidak diperlakukan sebagai logout. Root post-frame popUntil lama dihapus; navigasi akun ditangani redirect, sedangkan cleanup modal hanya menyasar overlay yang dimiliki.

Role exact whitelist: ADMIN `/admin`, USER `/patient`, PETUGAS `/staff`, DOKTER `/doctor`. Role tidak dikenal dan mismatch mendapat forbidden tanpa private UI flash. `/display` exact dengan query kosong dikecualikan sebelum guard akun; `/display-anything` tidak mendapat exemption. Kiosk tetap memvalidasi sesi perangkat melalui feature/backend.

`from` hanya menerima URI internal registered sesuai role terbaru, tanpa scheme/authority/fragment, slash ganda, backslash, traversal mentah/encoded, encoded separator, nested return, secret/unknown query, dan login/session loop. Raw dot segments ditolak sebelum Uri melakukan normalisasi. ID detail/clinic harus UUID. Enum query dibatasi; tab internal staff tetap lokal dan bukan query yang diizinkan. UTF-8 query rusak ditolak melalui penanganan FormatException di validator; tiga variasi memiliki tes regresi. `extra` tidak diperlukan untuk hydrate. Unknown path/error UI tidak mencetak raw URI/exception.

Browser account store tetap memory-only: hard refresh protected URL dapat memerlukan login kembali, lalu safe target divalidasi role dan dibuka. Ini berbeda dari secure-store restore Android. Backend tetap otoritas izin data dan ownership tiket.

## F. Navigation Contracts

Sidebar ADMIN memakai `go`; selected menu mengikuti URI. Pasien berpindah tab dengan `goBranch`; retap Reservasi kembali ke root list saat tidak busy. Booking/new/doctor adalah destination, tidak membuat reservasi lewat route resolution. Mode Home bukan branch keenam; history dormant dan reset-password tidak diaktifkan.

Native Back: overlay yang mengizinkan pop → child detail/booking ke root branch → root non-Home ke Home → perilaku platform dari Home. Busy booking memblokir native Back; logout/account eviction mengalahkan busy guard. Browser mengikuti history URL dan tidak memakai aturan perpindahan tab Android. Hard refresh/close ketika POST berjalan tidak dijamin tertahan; route reload tidak memutar POST.

Hash strategy default dipertahankan, tanpa PathUrlStrategy/rewrite. Server QA tetap mengembalikan 404 untuk path nested tanpa hash. Tidak menambahkan Android intent filter/app-link baru; registered in-app route dan system Back diuji terpisah dari OS app-link association.

## G. Provider & Resource Lifecycle

Counter widget memakai BlocObserver, identity repository/feed dan request spy. Navigasi berulang pada empat branch nonprofil mempertahankan tiga Cubit dan satu repository/feed, tanpa request tambahan pada navigation loop setelah pembacaan awal. Profil lazy satu instance setelah kunjungan pertama. Same-role account switch membuat tepat satu owner overview baru, menutup owner lama, dan mengganti retained profile. Native Back dan scope eviction diuji dengan barrier POST.

ADMIN mempertahankan satu host dan delapan Cubit selama sembilan modul, tanpa close saat navigasi. PASIEN mempertahankan tiga Cubit pada 12 navigasi; pembacaan API tetap 5→5, lalu profil menambah satu owner lazy. Ticket detail create/close 1/1 dan non-GET 0. PETUGAS/DOKTER masing-masing mempertahankan satu parent owner dan menambah satu owner profil. Display mempertahankan dua owner pada lima notifikasi SessionPhase akun dan explicit router refresh. Angka ini berasal dari tujuh record ROUTING_METRIC pada tes, tersedia pada evidence counter.

Cubit closure diamati lewat onClose; untuk Bloc, `isClosed` menyatakan penutupan event-controller telah dimulai sementara future cancellation dapat menyelesaikan asynchronous. Tes feature existing tetap memverifikasi stop feed/audio/controller, stale result dan idempotent close. Counter ini tidak dianggap pengukuran RAM/FPS. Angka browser/socket/audio aktual dicatat bersama evidence R3, bukan disimpulkan dari jumlah widget.

## H. GET-Only Hydration

Ticket destination memvalidasi UUID dan role, lalu PatientTicketCubit melakukan GET `/tiket/:id` melalui PatientRepository yang sama. Endpoint memverifikasi ownership; 403/404/error tidak memberi tombol QR atau data lama. Perubahan ID tiket pada route mengganti hydration; regresi valid→missing memastikan tombol/data tiket lama hilang. Tidak memakai appointmentId sebagai ticketId. QR dibuka secara eksplisit sebagai dialog transient, memakai Cubit detail yang sama tanpa owner kedua, tidak otomatis issue pada cold URL/reload. Dialog original dari daftar tetap tersedia dan lifecycle transient existing dipertahankan. Observer menutup overlay QR milik URI sebelumnya ketika route berganti; tidak memanggil removeRoute terhadap Page deklaratif.

Doctor destination membaca katalog dokter/layanan existing, memastikan dokter aktif dan hubungan poliklinik aktif yang tersedia, lalu GET jadwal. Jika clinic tidak ditentukan, hanya hubungan tunggal yang dapat disimpulkan; ambigu/404 mendapat feedback aman. Tidak menebak relasi atau memilih slot. Booking cold URL/new hanya hydrate pilihan GET, tanpa booking/tiket/QR POST.
